# 图检索（实体邻域召回）后续方案

> 状态：**待办，不阻塞现有功能**。记录在此是因为它需要一次独立的取舍，而不是随手能补的小改。
> 记录时间：2026-09-26。

## 现状：三层各司其职

| 层 | 角色 | 入口 |
|---|---|---|
| `WorldTraceStore` | **现场**：委派树原文（brief/context/summary/messages） | `world_trace` |
| `WorldKnowledgeStore` | **结论**：按 `(kind, signature)` 精确召回 + 依赖文件新鲜度校验 | `world_recall` |
| `WorldGraphStore` | **派生索引**：trace 落盘时抽实体、建确定性边（含最近节点邻接） | 仅 `edgesTouching` 供 `world_trace` 显示邻域 |

## 缺口

`world_recall` 只能按**精确签名**命中：同一条结论换个说法、换个签名就召回不到；跨 run
的「同一实体相关的历史观测」完全没有入口。这才是值得补的那一刀。

## 不建议做的事：用图检索「替代」TraceStore

- 图是从 trace **派生**的（`WorldTraceStore` 落盘时 `ingest`）：删掉原文既不能回读、也无法重建索引。
- 抽取有损（实体识别是启发式，会漏会串），一旦成为唯一来源，模型再也拿不到现场文本。
- DSH 的 rescope 也把「可追溯原文」放在派生索引之上。

## 建议方案

1. 保留三层不变，图作为 recall 的**第二条检索路径**：
   查询 → 命中实体（同名/别名）→ 取该实体近 N 条观测（时间衰减）+ 邻接边。
2. 每条结果都带 `sourceNodeId`，需要时回读原文。
3. 图分数**只用于排序**，不作为事实来源；误召回由模型看原文自行判断。

## 触发条件

等到真的撞上「同一实体换了说法就召回不到」的具体场景再做——届时图已经在写，
数据是现成的；反过来，如果现在删掉图，将来要做还得从零攒数据。
